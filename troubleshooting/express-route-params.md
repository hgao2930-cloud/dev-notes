# Express 路由参数顺序：res 被当成了 req

## 现象

（写你当时看到的：点「退出登录」没反应，页面没有任何提示；打开 Network 看到请求返回 500，响应体是统一的「服务器内部错误」）

## 排查过程

（你是怎么一步步定位的：① 先看 Network，确认请求确实到达了后端；② 看路由代码，逻辑看起来没问题，容易怀疑是别的地方；③ 去后端看真实报错，发现是 `res.clearCookie is not a function`）

## 根因

（Express 的处理函数**按位置传参**，第一个参数永远是 `req`。写 `(res)` 时，这个形参实际拿到的是 `req` 对象，而 `req` 上没有 `clearCookie`）

## 解决

（用 `_req` 占住第一个位置：`(_req, res) => { ... }`）

## 教训

（用不到的参数也要占位，不能省略；前端看到 500 时第一时间看后端日志，统一错误处理会掩盖真实报错）

## 延伸

（为什么 JS 不能"跳过"中间的参数；Express 中间件的四参数错误处理器也是同一个道理）
